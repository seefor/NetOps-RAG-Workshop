# Four-Hour Delivery Guide

The workshop fills four hours only when each lab includes inspection, failure analysis, discussion, and improvement. Running the commands alone is not enough.

## Instructor pacing rule

For each lab:

1. Explain the operational problem.
2. Demonstrate the first command.
3. Let students run it.
4. Inspect retrieval or output together.
5. Introduce a failure or conflicting source.
6. Let students improve the query, filter, prompt, or data.
7. Debrief the engineering lesson.

## Time protection

Use the scenario cards when students finish early. Skip stretch challenges when setup or model speed consumes time. Never skip the source-authority and prompt-injection discussion; those are core production lessons, not optional security extras.

## Suggested interaction prompts

- “Which source would you trust during an outage, and why?”
- “What did retrieval find that generation hid?”
- “What evidence is missing?”
- “Would you allow this answer into a change ticket?”
- “What part belongs in RAG, and what part belongs in pyATS, Batfish, NetBox, or an authenticated automation workflow?”
