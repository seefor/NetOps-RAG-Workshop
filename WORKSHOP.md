# RAG for Network Operations — Four-Hour Workshop

## Goal

Build a RAG-powered NetOps assistant that can retrieve trusted operational knowledge, explain evidence with citations, expose uncertainty, and remain inside a read-only safety boundary.

## Schedule

| Time | Section |
|---|---|
| 0:00–0:20 | Why RAG for NetOps |
| 0:20–0:45 | Architecture and providers |
| 0:45–1:25 | Lab 1 — ingest and retrieve |
| 1:25–1:35 | Break |
| 1:35–2:15 | Lab 2 — multi-vendor configuration evidence |
| 2:15–2:55 | Lab 3 — incident investigation |
| 2:55–3:05 | Break |
| 3:05–3:35 | Lab 4 — guardrails and evaluation |
| 3:35–3:47 | Streamlit and provider switching |
| 3:47–4:00 | Production architecture, recap, and close |

## Lab rhythm

Every lab follows the same delivery pattern:

> Explain → build → inspect → intentionally break → improve → debrief

Running the commands alone is not the workshop. The teaching happens in inspecting retrieved evidence, challenging assumptions, comparing sources, and explaining where RAG should stop.

## Bonus

The optional Hermes Desktop NetOps Incident Copilot bonus can be delivered after the four-hour session or used to replace the final capstone share-out. It demonstrates how the RAG knowledge layer can be exposed through MCP and combined with controlled read-only operational evidence and a reusable investigation skill.
